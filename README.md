# 土器実測図トレース（Webアプリ版 ver.1.0.0）

鉛筆で描いた土器実測図のスキャン画像を下に敷き、マウスでなぞってレイヤー・線幅つきのベクター線画にするブラウザアプリです。完成図は SVG で書き出し、Illustrator で開けます。

- サーバー側の処理はありません。画像の読み込み・自動トレース・保存はすべて利用者のブラウザ内で行い、データを外部へ送信しません。
- HTTPS で公開すると、インストール（PWA）とオフライン利用ができます。
- 利用者向けの説明書：`docs/manual.pdf`（アプリ画面上部の「使い方（PDF）」ボタンからも開けます）

## ファイル構成

```
index.html             アプリ本体の画面
css/app.css            見た目
js/app.js              本体の処理
js/autotrace.js        自動トレース（細線化→ベクター化）
js/sample.js           作例の下図（画像を埋め込み）
js/register-sw.js      オフライン対応の登録
sw.js                  Service Worker（オフライン用キャッシュ）
manifest.webmanifest   インストール用の設定
icons/                 アプリのアイコン
docs/manual.pdf        利用者向けマニュアル
.nojekyll              GitHub Pages で Jekyll 処理を止めるための空ファイル
```

## GitHub Pages で公開する手順

1. GitHub で新しいリポジトリを作ります（例：`doki-trace`）。公開にするには、無料プランの場合はリポジトリを Public にします。
2. この ZIP を展開し、**中身（index.html がある階層）をリポジトリの一番上**にアップロードします。
   - ブラウザで行う場合：リポジトリの「Add file」→「Upload files」に、展開したファイルとフォルダーをまとめてドラッグします。
   - `.nojekyll` は隠しファイルのため、エクスプローラーで表示されないことがあります。なくても動作しますが、可能なら一緒にアップロードしてください。
3. リポジトリの「Settings」→「Pages」で、「Build and deployment」の Source を「Deploy from a branch」、Branch を `main`、フォルダーを `/(root)` にして保存します。
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。この URL を学生に知らせてください。

※ GitHub の画面表記は変わることがあります。

## アプリを更新するとき

1. 変更したファイルを上書きでアップロードします。
2. `sw.js` の先頭にある `VERSION` の値を変えます（例：`doki-trace-v1.0.0` → `doki-trace-v1.0.1`）。
   - これを変えないと、利用者の端末に古いファイルが残ることがあります。
3. 利用者は、インターネットにつながった状態でページを再読み込み（F5）すれば新しい版になります。

マニュアルを差し替える場合は `docs/manual.pdf` を同じ名前で上書きし、同様に `VERSION` を変えてください。

## 手元で動作を確認する

ファイルをダブルクリックして開いても使えますが、オフライン機能とインストールは `https://` か `localhost` でのみ動きます。手元で確認する場合は、展開したフォルダーで次を実行し、ブラウザで `http://localhost:8000/` を開きます。

```
python -m http.server 8000
```

## 外部への接続

- Google Fonts（書体の読み込み）のみ。つながらない環境では、パソコンにある書体で表示されます。

## 注意

- 作例の下図（`js/sample.js`）は、実測図スキャンの一部です。公開前に、掲載してよいか確認してください。差し替える場合は、別の画像を data URI にして `window.DOKI_SAMPLE_IMG` に入れます。
